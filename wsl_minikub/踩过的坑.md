# 1. 环境准备与工具安装
> **前提条件**：本机已安装 Docker（WSL 环境推荐 Docker Desktop，并确保 WSL 集成已开启）,也可以使用apt部署docke

安装 Minikube：通过 curl下载最新版本的二进制文件，并使用 sudo install命令将其移动到系统可执行路径 /usr/local/bin/下。
```bash
#拉取谷歌镜像
curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64
#或者国内镜像
curl -LO https://kubernetes.oss-cn-hangzhou.aliyuncs.com/minikube/releases/latest/minikube-linux-amd64
#安装minikube
sudo install minikube-linux-amd64 /usr/local/bin/minikube
```

安装 Kubectl：通过 curl获取 Kubernetes 官方最新的稳定版发布信息，动态构造下载链接来安装 kubectl命令行工具。
```bash
#安装kubectl
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"

# 验证 kubectl 安装
kubectl version --client
```
# 2. 网络配置

修改 DNS：为了解决可能的网络解析问题，编辑 /etc/resolv.conf文件，手动添加了公共 DNS 服务器 114.114.114.114。
```bash
# 编辑/etc/resolv.conf
sudo nano /etc/resolv.conf

# 在已有的nameserver下加上下面这个
nameserver 114.114.114.114
```
> ⚠️ **注意**：WSL 的 `/etc/resolv.conf` 由系统自动管理，重启 WSL 后会被覆盖。如需永久生效，请执行：
> ```bash
> sudo tee /etc/wsl.conf <<< '[network]\ngenerateResolvConf = false'
> sudo rm /etc/resolv.conf
> sudo nano /etc/resolv.conf
> ```
# 3. 应用部署 (Nginx)

强制使用本地镜像：编写了一个 Deployment 的 YAML 配置文件。关键点在于设置了 imagePullPolicy: Never，这强制 Kubernetes 只使用本地已有的镜像，而不去远程仓库拉取。
- 前提是 WSL 的 Docker 里已经有 nginx:latest镜像（通过 docker pull获得），然后用 minikube image load灌进虚拟机
```bash
#在当前路径下创建yaml文件
sudo nano nginx-local.yaml
```

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: hello-minikube
spec:
  replicas: 1
  selector:
    matchLabels:
      app: hello-minikube
  template:
    metadata:
      labels:
        app: hello-minikube
    spec:
      containers:
      - name: hello-minikube
        image: nginx:latest
        imagePullPolicy: Never   # 关键：强制只用本地镜像
        ports:
        - containerPort: 80
#保存并退出
```
# 4. 解决镜像拉取痛点 (关键步骤)

背景：Minikube 在创建节点时默认会尝试从网络拉取镜像，如果网络不通畅会导致节点启动失败。

解决方案 (Kicbase 底座)：

从阿里云镜像仓库 (registry.cn-hangzhou.aliyuncs.com) 手动拉取 Minikube 的基础运行环境镜像 (kicbase:v0.0.50)。
- kicbase 版本必须与 minikube CLI 版本匹配。可通过 minikube start --dry-run查看所需版本，或在 Minikube 官方 Release
中查询对应关系。
```bash
docker pull registry.cn-hangzhou.aliyuncs.com/google_containers/kicbase:v0.0.50
```
使用 docker tag命令将拉取的镜像重新打上标签，使其符合 Google 官方仓库的命名规范 (gcr.io/k8s-minikube/kicbase:v0.0.50)，从而“欺骗”Minikube 使用本地镜像启动节点。
```docker
docker tag registry.cn-hangzhou.aliyuncs.com/google_containers/kicbase:v0.0.50 gcr.io/k8s-minikube/kicbase:v0.0.50
```
# 5.总结启动验证是否可以在浏览器访问集群内服务
> **二选一**：

> - **方式 A（推荐）**：直接指定阿里云源，省掉 docker tag 步骤（即下方第一种）。

```bash
# 1. 起集群（用 --base-image 直接指定阿里云源，省掉 docker tag）
minikube start \
  --driver=docker \
  --base-image="registry.cn-hangzhou.aliyuncs.com/google_containers/kicbase:v0.0.50" \
  --image-mirror-country=cn

kubectl cluster-info    # 应看到控制平面和 CoreDNS 都在运行
kubectl get nodes       # 应看到 minikube 节点状态为 Ready

# 2. 把 nginx 镜像灌进 Minikube 虚拟机（关键！否则 Pod 起不来）
minikube image load nginx:latest

# 3. 部署 Nginx（YAML 里已设 imagePullPolicy: Never）
kubectl apply -f nginx-local.yaml

# 4. 验证 Pod 状态
kubectl get pods   # 看到 Running 再继续

# 5. 暴露 Service（只需第一次）
kubectl expose deployment hello-minikube --type=NodePort --port=80

# 6. 浏览器访问
minikube service hello-minikube
```

> - **方式 B（备选）**：如果方式 A 因 kicbase 版本缺失而失败，可先执行第4节的 docker pull + docker tag，再用下方第二种启动。

> **注意**：此 YAML 设置了 `imagePullPolicy: Never`，因此执行 `kubectl apply` 之前，必须确保 Minikube 虚拟机内已有 `nginx:latest` 镜像。具体操作见第5节步骤2。

```bash
# 1. 起集群（kicbase 已 docker tag 好的前提下）
minikube start --driver=docker

kubectl cluster-info    # 应看到控制平面和 CoreDNS 都在运行
kubectl get nodes       # 应看到 minikube 节点状态为 Ready

# 1.5 把 nginx 镜像灌进 Minikube 虚拟机
minikube image load nginx:latest

# 2. 部署 Nginx（imagePullPolicy: Never，靠 minikube image load nginx:latest）
kubectl apply -f nginx-local.yaml

# 3. 验证 Pod 起来
kubectl get pods   # 看到 Running

# 4. 暴露 Service（只需第一次）
kubectl expose deployment hello-minikube --type=NodePort --port=80

# 5. 浏览器访问
minikube service hello-minikube
```

---
这条命令应该很重要，但是我第二次部署的时候就没有用到，如果未来哪一天再次部署找不到问题，可以试一试这一条命令
```docker
kubectl run hello-minikube --image=nginx --image-pull-policy=IfNotPresent
```
在 Kubernetes 集群中创建一个资源，资源名称为 hello-minikube，
指定容器使用的镜像为官方的 Nginx 镜像（默认从 Docker Hub 拉取），
设置镜像拉取策略：只有当本地节点上不存在该镜像时，才从远程仓库拉取；若本地已有则直接使用，避免重复下载。
