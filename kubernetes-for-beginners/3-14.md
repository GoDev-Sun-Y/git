# 部署应用
这是用来在集群中启动一个新应用（如 Nginx）的命令。
命令：
```bash
kubectl run nginx --image nginx
```
记忆点：
- kubectl run：表示“运行”一个容器。  
- nginx：这是你给这个应用起的名字（Deployment 名称）。  
- --image nginx：指定使用的镜像名称。

# 查看资源状态
这是用来检查刚才部署的应用是否成功运行（是否变成 Running 状态）的命令。
命令：
```bash
kubectl get pods
```
记忆点：
- kubectl get：表示“获取”集群里的资源。
- pods：表示你想看的是“Pod”列表（K8s 中最小的调度单位）。
- 输出关注点：​ 关注 `STATUS`列是否为`Running`，以及 READY列是否为 1/1。


# 更详细的查看
`kubectl describe pod nginx`
执行该命令后，你会看到一个很长的报告。重点关注以下几个区块：
- Name: 确认是否是你要查的那个 Pod。
- Status: 当前的生命周期状态。
- Containers: 容器状态。
- Ready: 是否就绪。
- State: 当前状态（Waiting, Running, Terminated）。
- Reason: 状态变更的原因（例如 Error, Completed）。
- Events (最重要): 位于输出的最下方。
这里记录了时间线，例如：“拉取镜像成功”、“调度到 node1 成功”、“端口冲突”等。
排障绝招：如果 Pod 起不来，90% 的原因都能在 Events 里找到直接的报错信息。

# get pods 扩展
- kubectl get pods：基础命令，获取 Pod 列表。
- -o wide：格式选项（Output wide），意为“宽格式”。它会比默认输出多显示几列关键的网络和调度信息。

#### 输出字段解读
执行该命令后，除了常规的 NAME、STATUS、RESTARTS外，还会多出以下核心字段：
- IP(172.17.0.3)：
    - Pod 在集群内部的虚拟 IP 地址。
    - 这意味着其他 Pod 或服务可以通过这个 IP 访问它。
- NODE(minikube)：
    - 当前 Pod 被 Kubernetes 调度到的物理机或虚拟机节点名称。
    - 这说明 Pod 已经成功分配到了具体的运行环境上。
- NOMINATED NODE(<none>)：
    - 通常用于调度失败时的备用节点提名，正常情况下为空（<none>），表示一切正常。
